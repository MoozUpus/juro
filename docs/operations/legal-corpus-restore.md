# Legal corpus restore rehearsal

Use this procedure for an actual recovery or a specific recovery-path defect. Routine releases, activations and retirements reuse accepted evidence under the [verification policy](./legal-corpus-verification.md).

## Current R2-native release

1. Restore the body-free legal D1 control data into an isolated database and verify integrity, release roots and the capacity gate.
2. Verify the complete Evidence R2 and derivative-index R2 inventory roots and representative object hashes.
3. Open the pinned BM25 manifest; validate every declared analyzer, segment, byte range, statistic and hash; then run bounded sparse probes.
4. Create a compatible off-side Vectorize index only from hash-verified reusable R2 embeddings. Do not call the embedding provider.
5. Wait for the final mutation, start a fresh listing and prove exact vector ID, count and metadata parity.
6. Run representative current, historical and temporal hybrid queries. Inject each declared-lane failure and verify the strict Source Ladder.
7. Record content-free evidence only.

A count-only vector check, cache-dependent restore, mixed release components, missing lane or provider call fails the rehearsal.

## Historical archive

The accepted pre-retirement D1/Qdrant archive may be restored only into an isolated, non-routed environment for forensic investigation. Never attach it to a live Worker, recreate a retired namespace or use it as an Activation Set. Preserve the archive and immutable migration history without repeating the completed audit.

A timeout, incomplete import or `SQLITE_NOMEM` is a failed probe, not integrity evidence.
